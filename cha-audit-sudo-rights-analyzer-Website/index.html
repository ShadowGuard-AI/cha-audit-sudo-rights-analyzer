One File, Read Closely

cha-audit-sudo-rights-analyzer analyses a sudoers file for overly permissive or insecure sudo rights assignments, highlighting potential privilege escalation vulnerabilities.

A fault carried over from the README

The README follows that opening with a grafted sentence, a fragment beginning with a dash, claiming a focus on auditing system configuration settings against security hardening benchmarks such as CIS benchmarks, on checking for insecure configurations and generating reports with recommendations for remediation, and on supporting Windows, Linux, and macOS.

The code does none of that wider work: main.py reads one sudoers file, and the only grants it flags are the ones described on the behaviour leaf below. The graft stays visible because it stands in the README, and it is not allowed to pass as a description of the program.

Who May Run Anything

-hShows the help message and exits.
-fAlso written --sudoers_file. Takes the path to the sudoers file, default /etc/sudoers. The README lists this flag with the words No description provided; the description used here comes from the argument parser in main.py.
-oAlso written --output_file. Takes the path to the output file and is optional. The README gives it no description either, so the same note applies.
-vAlso written --verbose. Enables verbose output. This is the one flag the README does describe beyond -h.
blankA fifth ruled line, left blank in the register, marks the positional argument that does not exist: the file path arrives by flag, never by position.

What Passes Unseen

Comment lines and empty lines are skipped, lines that are not user specifications are skipped, and the command part of each remaining line is compared on its own. A line whose command part is exactly ALL earns the finding that a user or group can run any command as root and should consider restricting it, and if that same line also carries NOPASSWD: it earns a second finding, that NOPASSWD for all commands is a security risk.

Only an Exact ALL Is Flagged

Nothing short of that exact ALL is flagged: wildcard paths, shell escaping editors or pagers, and a single command granted as root with NOPASSWD all pass unseen. Include lines are met as comment shaped lines and skipped, so drop in files pulled in by those lines are never opened, and only the one named file is read.

When the File Cannot Be Read

A missing file ends the run with exit 1. A file that cannot be read returns no result and ends the run with exit 1 rather than being summarised as clean. A report that cannot be written also ends the run at exit 1. When no findings exist, the words No vulnerabilities found. print only in verbose mode. Otherwise findings print to the console, or to the output file when -o is given, each with its line number, its description, and the line content.
